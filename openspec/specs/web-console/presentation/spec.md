# web-console/presentation

## Purpose

定义控制台如何呈现诊断结果，使未经最终审查的内容在视觉上不可能被误认为最终结论，
并让用户能查看证据来源与检索轨迹。

## Requirements

### Requirement: 最终与阶段性答案区分

界面 SHALL 对阶段性答案显示持久的未通过最终审查标记，且 MUST NOT 使用与最终答案
相同的成功样式。

#### Scenario: 阶段性答案呈现

- **WHEN** run 返回的答案被标记为阶段性
- **THEN** 该答案附带"未通过最终审查"标记，并使用警示样式

#### Scenario: 最终答案呈现

- **WHEN** run 返回通过审查的最终答案
- **THEN** 不显示警示标记，并按正常答案样式呈现

#### Scenario: 无答案

- **WHEN** run 结束但没有可用答案
- **THEN** 显示终止原因，不显示空答案卡片

### Requirement: 未批准操作建议不呈现

对于未通过审查的阶段性结果，界面 MUST NOT 展示未获批准的操作建议。

#### Scenario: 阶段性结果含操作建议

- **WHEN** 阶段性结果包含工作流未批准的操作建议
- **THEN** 界面不渲染这些建议，只保留暂定断言与已核验证据

### Requirement: 证据展示

界面 SHALL 展示被引用证据的虚拟路径、行号、章节、逐字引文，以及该证据声明的
检索义务。

#### Scenario: 查看证据

- **WHEN** 用户打开某次回答的证据面板
- **THEN** 每条已核验证据显示路径与行号、章节、逐字引文和绑定的检索义务

#### Scenario: 区分引用与未引用

- **WHEN** 某次运行同时存在被草稿引用的证据和未被引用的已核验证据
- **THEN** 界面能区分两者，不把未引用证据呈现为答案依据

### Requirement: 轨迹展示

界面 SHALL 以默认折叠的方式展示检索计划、义务覆盖状态、Critic 决策和工具调用轨迹。

#### Scenario: 展开轨迹

- **WHEN** 用户展开某次回答的轨迹面板
- **THEN** 显示证据义务及每项是否已绑定、Critic 决策与说明、以及有界的工具调用记录

#### Scenario: 展开不改变结论

- **WHEN** 用户展开或收起轨迹面板
- **THEN** 答案内容与状态标记保持不变

### Requirement: 运行模式可见

界面 SHALL 常驻显示当前会话是否为 dry-run，并在提交前可见该状态。

#### Scenario: dry-run 会话

- **WHEN** 会话以 dry-run 创建
- **THEN** 界面显示 dry-run 徽标，且所有回答都带该标识
