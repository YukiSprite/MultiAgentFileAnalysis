# web-console/progress

## Purpose

把诊断过程中已经记录的审计事件以流式方式呈现给浏览器，让用户在长时间运行中看到
当前阶段与工具活动，并在结束时收到一个明确的终止事件。

## Requirements

### Requirement: 进度事件流

系统 SHALL 为每个 run 提供可订阅的事件流，按发生顺序推送工作流阶段变更和工具调用。

#### Scenario: 阶段变更可见

- **WHEN** 客户端订阅一个正在执行的 run 且工作流进入新阶段
- **THEN** 在流中收到包含该阶段名称的事件

#### Scenario: 工具调用可见

- **WHEN** 执行期间发生一次只读工具调用
- **THEN** 在流中收到包含工具名、路径与查询的事件

#### Scenario: 订阅未知 run

- **WHEN** 客户端订阅不存在的 run
- **THEN** 返回明确错误，不建立事件流

### Requirement: 终止事件

每个 run SHALL 在其真正结束时推送且只推送一个终止事件，其中包含最终状态、答案文本与
阶段性标记；终止事件 MUST 由执行器在工作流返回后合成。

等待人工输入不是 run 的结束。该状态 SHALL 推送一个暂停事件并结束当前事件流，
后续恢复 SHALL 继续同一个 run，直到真正的终止事件。

#### Scenario: 正常完成

- **WHEN** run 以通过审查结束
- **THEN** 收到一个终止事件，包含完成状态与非阶段性答案

#### Scenario: 等待人工输入

- **WHEN** run 停在等待人工输入
- **THEN** 收到一个暂停事件，包含等待状态与阶段性答案，当前事件流结束；恢复后同一 run 仍可收到终止事件

#### Scenario: 恢复后终止

- **WHEN** 暂停的 run 被恢复并最终结束
- **THEN** 该 run 只收到一个终止事件，且不重复推送

#### Scenario: 只推送一次

- **WHEN** run 已推送终止事件后再次被查询或重新订阅
- **THEN** 不会重复推送第二个终止事件

### Requirement: 事件有界

系统 SHALL 对每个 run 保留的事件数量设上限，超出后丢弃最旧的事件，以避免长时间
运行导致内存无界增长。

#### Scenario: 事件超过上限

- **WHEN** 单个 run 产生的事件数超过配置上限
- **THEN** 只保留最新的有限数量事件，查询与订阅仍能拿到终止事件

### Requirement: 事件不改变工作流语义

事件推送 MUST NOT 阻塞、重排或改变工作流的阶段决策与证据校验结果。

#### Scenario: 订阅者缺席

- **WHEN** 没有任何客户端订阅该 run
- **THEN** run 正常执行完成，结果与有订阅者时一致

#### Scenario: 审计写入失败

- **WHEN** 某个事件接收端写入失败
- **THEN** 诊断流程仍继续，失败被隔离在该接收端内部
